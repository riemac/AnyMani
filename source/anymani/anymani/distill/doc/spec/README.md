# Distill 工程规范索引

本目录保存 AnyMani `distill` 子项目的工程规范。规范把已经拍板的科研语义翻译为代码所有权、稳定接口、数据流、缓存、测试和分阶段实施边界，但不替代 `Research/总体/ssl/当前设计/` 中的科学合同，也不把尚未运行的候选写成已经验证的能力。

| --- | --- | --- |
| [`多锚点整手条件隐式场工程规范.md`](多锚点整手条件隐式场工程规范.md) | 当前主规范 | 记录 cross-embodiment、task-free 的运动学—几何特权预训练主线，以及资产、机器人、表征、模型、训练、测试与证据边界 |

## 事实来源优先级

1. 物理定义、数学合同、规范变换和科研结论以 `Research/总体/ssl/当前设计/` 与 `Research/总体/ssl/验证证据/` 为科研事实源。
2. 本目录拥有已经合意后的工程翻译，包括 package ownership、接口方向、阶段闸门、缓存和测试组织。
3. 源码、配置和测试只证明已经实现并运行的事实；规范不得用未来时设计替代实际证据。
4. `distill/doc/` 下的概念图用于建立直觉，不能独立冻结符号、网络、数据或训练合同。

## 使用方式

每个实施阶段开始前，应从主规范读取该阶段的输入、输出、禁止项和验收条件，再为该阶段单独拟定决策完备的实施计划。前一阶段的运行证据可以触发后续候选，但不能由实施者在代码中静默改变主规范。

当前主线是多锚点整手条件隐式 Gaussian 场。解析直接几何压缩、粗尺度几何闭包、独立场灵敏度解码器、替代集合编码器和目标手几何适配均保留为具名候选；目录或接口存在不表示候选已经进入正式实验。

## 维护规则

- 规范修改必须说明它是在纠正文档漂移、落实新的科研合意，还是记录阶段证据。
- 尚未冻结的数值应写成候选范围、选择指标和停止条件，不能伪装成默认超参数。
- 新增可执行声明、配置字段、注册项、训练入口或第三方依赖前，仍需按上级 `AGENTS.md` 的 declaration gate 获得授权。
- source code 不得 import、解析或要求 `Research/` vault 存在；本目录必须足以让实现者理解工程合同。
