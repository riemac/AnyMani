## 子项目定位

本子项目主要服务于**手部资产的前序工程**，核心目标不是直接参与 Isaac Lab 运行时仿真逻辑，而是为后续流程提供稳定、清晰、可枚举的资产描述与生成基础。

它主要负责：

- 手部资产的**声明式配置描述**
- 多样化手资产的**组合生成**
- 与 URDF / mesh / primitive 几何相关的**规范化建模**
- 为后续 URDF 导出、SDF 预处理、图构建、训练环境接入提供统一输入

它暂时不负责：

- RL 环境本身的 step/reset 逻辑
- Isaac Lab manager / term 的运行时调度
- 训练脚本与算法实现

## 核心开发原则

### 1. 声明式配置驱动

本子项目以**声明式配置驱动**为核心风格。

优先写：“对象是什么”的配置结构。

谨慎写：

- 大量过程式脚本把逻辑揉在一起
- 还没稳定的想法直接写死进运行时流程

原则是先把**结构和约束讲清楚**，再把“怎么生成”“怎么导出”“怎么消费”逐层接上。

### 2. 职责分层

遵守 SOLID 设计原则，推荐分层如下（暂定）：

本子项目遵循以下四个逻辑层，每层职责独立，不得混写：

- **Schema 层**：声明结构、字段校验、默认值、规范化解析
- **生成层**：组合、枚举、筛选、采样规则
- **导出层**：URDF / XML / mesh / yaml / metadata 输出
- **消费层**：SDF、图结构、环境接入

新增代码前，先判断它属于哪一层。
如果一段逻辑跨越多层，应拆分而不是混写

### 3. 面向科研迭代

这是科研代码，不是产品代码。

因此这里的设计优先级是：

1. 建模语义清楚
2. 约束边界清楚
3. 方便修改和枚举
4. 方便后续接入 AI 协作

只要不破坏结构清晰性，不必过早追求复杂抽象。

## 代码风格

### 1. 数据优先

优先使用：

- `@dataclass`
- 明确类型标注
- `__post_init__` 做规范化与一致性检查

### 2. 命名

- 配置类统一用 `*Cfg`
- 几何、关节、手指、手掌、整手等层级名称要直观
- 不要为了抽象而抽象

### 3. 校验

凡是 schema 层可以提前发现的问题，尽量在这里报错：

- 名称非法
- joint limit 非法
- 运动学链断裂
- 重名
- 几何参数为负

不要把明显错误拖到导出阶段或仿真阶段才暴露。
